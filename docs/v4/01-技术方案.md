## 2. 目标产品形态

从 UiTab 实测（04 文档）提取的功能全集：

**主界面——单一绝对定位网格，无分区**
- 全屏壁纸背景（静态图 / 动态视频）
- 左上：**悬停展开的模式胶囊**（极简 / 标准 / 隐私）；右上：42×42 圆形头像
- 搜索栏行：`y=100`，高 50，居中，胶囊输入框 772×54（`rgba(255,255,255,.5)` + 2px 边框）
- 主网格：`60px` 单元格，卡片四边内缩 25px（`尺寸 = 单位×60 − 50`），24 列 × 10 行，固定 1920 设计稿坐标系、垂直居中
- 网格内混排：**网址图标（2×2）/ 图标格容器（4×2、4×4、8×4）/ 小组件（4×2、4×4、8×4、2×4）**
- 每张卡片下方 **14px 白色居中名称标签，常驻显示**
- 卡片样式：**不透明白底 + 16px 圆角**（不是毛玻璃）
- 横向翻页：每页宽 1920，页面 N 坐标 = 页面 1 + `N×1920`
- 底部 Dock：`bottom:0`，高 122，padding 16；8 个 98×98 应用位（图标 66×66）+ 4 个功能按钮（添加 / 个性化 / 广场 / 设置）

**一期要落地的小组件**：新闻热点、时钟、下班倒计时（**单卡片多条目**）、纪念日、日历、待办、图标格容器、网址图标

**右键菜单（实测 10 项）**：打开方式 · 搜索栏 · Dock栏 · 极简模式 · 隐藏项目 · 搜索引擎 · 吉祥物 · 站内消息 · 更新记录 · 关于我们

**四套内置风格皮肤**：经典 / 光感 / 暗黑 / 黑紫 + 首次访问欢迎弹窗（4 风格卡 + 「应用风格」）。四套仅为出厂初始值，用户可自定义配色、改名、新建、删除、覆盖（见 02 §6.1）。
**壁纸分类**：极简 / 动漫 / 风景 / 更多

**右侧抽屉（4 个面板）**
1. **添加**：自定义网站 / 小组件 / 网址导航（三个 tab，组件卡带左右翻页）
2. **界面广场**：大厅 / 分享 / 我的；热门推荐 + 用户分享；分类筛选；卡片带预览图、点赞数、日期、「详情」「应用」；分页
3. **个人信息**：主页 / 备份数据；登录注册；立即备份 / 恢复默认；备份列表
4. **个性化 / 设置**：壁纸、风格、布局、搜索引擎、数据管理

## 3. 技术选型与理由

### 3.1 先回答两个疑问

**「TS + esbuild」和「React + Vite」能合在一起吗？**
能，而且是同一套。Vite 内部就用 esbuild 做 TS/JSX 转译与依赖预构建，生产打包才切到 Rollup。所以：

- `React + Vite + TypeScript` = 一个方案，不是两个
- v3 的 `esbuild` 构建脚本在 v4 被 Vite 取代，**不是叠加**

**「Vue3 + Vite」能一起吗？**
能，也是完整方案。但**不能把 React 和 Vue 塞进同一个应用**——双运行时、双构建配置、双组件规范，维护成本翻倍，收益为零。这是要避开的。

### 3.2 选型对比

| 方案 | 效果能做到吗 | 维护成本 | 结论 |
| --- | --- | --- | --- |
| 原生 TS + esbuild（沿用 v3） | 能，但小组件编排、抽屉多面板、拖拽、模板渲染都要自建状态与渲染约定，v4 的 UI 复杂度已超出「手写 DOM」的舒适区 | 中高：每加一个小组件都要写一套 DOM 增删改 | ✗ |
| **React 18 + Vite + TS** | 能，且小组件天然就是组件；拖拽有 dnd-kit；与云笺集同栈 | **低**：与云笺集共享类型、请求层、工程工具链 | **✓ 采用** |
| Vue 3 + Vite | 能 | 中：与云笺集栈不一致，无法共享规范与工具链 | ✗ |

**决定采用 React 18 + Vite + TypeScript。** 决定性理由不是「React 更好」，而是**云笺集已经是 React 18 + Vite + TS，且带一套成体系的设计令牌规范**。v4 要与它共享账号、后端部署方式与工程工具链，栈统一能让：

- 设计令牌的分层做法（字号/层叠/圆角阶梯）可借鉴；**但云笺集的紫色禁令不继承**——Thrilled 的界面风格是用户可自定义的皮肤数据，不做颜色限制（见 02 §6.1）
- API 客户端、错误包络解析、Bearer 持久化逻辑可参考/复用
- 类型定义（用户、模板、快照）可在两项目间保持一致
- 只有一套构建与 lint 心智，而不是两套

**代价（必须承认）**：v3 的视图层要重写，构建从 esbuild 换到 Vite，磁贴/分类/设置面板等模块要按组件重做。数据层通过「框架无关的 service 层」保留，把重写范围限制在视图。

### 3.3 配套依赖（待确认，见 03 文档）

| 用途 | 候选 | 说明 |
| --- | --- | --- |
| 状态管理 | `zustand` | 轻量，适合「全局设置 + 布局 + 抽屉状态」 |
| 拖拽排序 | `@dnd-kit/core` + `sortable` | 支持网格排序与 Dock 排序；一期可先用原生 HTML5 DnD 起步 |
| 数据校验 | `zod` | v3 已在 devDependencies 中使用；用于模板/快照 payload 校验 |
| 样式 | 原生 CSS + CSS 变量令牌 | 令牌分层方式借鉴云笺集 `DESIGN-SPEC.md`（字号/层叠/圆角），但**风格皮肤的颜色不受其约束**；不引入 CSS-in-JS |
| 构建 | `vite` + `@crxjs/vite-plugin` 或自写 MV3 构建脚本 | 需评估 CRXJS 对 MV3 稳定版的支持情况（见 03 文档待决策） |

## 4. 服务拆分与鉴权复用

### 4.1 拓扑

```
┌──────────────────────────── 云笺集服务器（同一台机器） ────────────────────────────┐
│                                                                                 │
│  nginx :80                                                                      │
│   ├─ /            → /srv/cloudletter/workbench   (云笺集 SPA)                    │
│   ├─ /api/        → 127.0.0.1:3012               (cloudletter-server)           │
│   ├─ /portal/     → /srv/portal                  (拾光集导航页)                   │
│   ├─ /newtab-api/ → 127.0.0.1:3020               (thrilled-server) ← 新增        │
│   └─ /healthz     → 127.0.0.1:3012                                              │
│                                                                                 │
│  systemd: cloudletter-server(:3012)  ← 已有                                      │
│  systemd: thrilled-server(:3020)     ← 新增，独立单元、独立 DB                    │
│                                                                                 │
│  127.0.0.1:3012  ◄── 内部调用 /api/v2/auth/me 校验 token（thrilled-server 发起）  │
└─────────────────────────────────────────────────────────────────────────────────┘
                                    ▲
                                    │ HTTPS? 否，本期明文 HTTP + Bearer
                                    │
                        ┌───────────┴────────────┐
                        │  Thrilled v4 扩展       │
                        │  chrome-extension://…   │
                        │  本地: chrome.storage   │
                        │        + IndexedDB      │
                        └─────────────────────────┘
```

### 4.2 为什么独立服务

按用户要求：**使用云笺集服务器，但服务独立成项目，避免两个项目服务混合导致维护问题。**

因此：

- **独立进程**：`thrilled-server` 独立 systemd 单元，监听独立端口（建议 `3020`）
- **独立数据库**：独立 SQLite 文件（如 `thrilled.db`），与 `cloudletter.db` 物理隔离。云笺集挂了不影响新标签页本地使用；thrilled 库损坏不影响云笺集内容
- **独立仓库/目录**：与 `d:\cloudletter` 平级，如 `d:\thrilled-server`
- **共享的只有账号**：通过 HTTP 复用云笺集鉴权，不共享数据库文件（避免 SQLite 多进程写锁竞争）

### 4.3 账号复用方案（不共享数据库）

```
扩展                         thrilled-server                     cloudletter-server
 │                                  │                                    │
 │ POST /newtab-api/api/v2/auth/login（email + password）                 │
 │─────────────────────────────────►│                                    │
 │                                  │ POST /api/v2/auth/login            │
 │                                  │───────────────────────────────────►│
 │                                  │ ◄── { token, expiresAt }           │
 │                                  │ 回写 Set 到扩展；本地存 UserRef     │
 │ ◄── { token, user, expiresAt }   │                                    │
 │                                  │                                    │
 │ 后续请求 Authorization: Bearer <token>                                │
 │─────────────────────────────────►│ GET /api/v2/auth/me (Bearer)       │
 │                                  │───────────────────────────────────►│
 │                                  │ ◄── { id, email, nickname, avatar }│
 │                                  │ 内存缓存 60s，避免每请求一跳        │
```

要点：

1. **单一账号真相源在云笺集**：密码、锁定、验证码、会话生命周期全部由云笺集负责，thrilled-server 不落密码、不签发第二套会话
2. **本地只存映射**：`UserRef { remoteUserId, email, nickname, avatar }`，用于关联快照/模板归属
3. **性能**：thrilled-server 与 cloudletter-server 同机，走 `127.0.0.1`，一跳开销可忽略；再加 60 秒 token→user 内存缓存
4. **失败降级**：云笺集不可达时，云功能报错但不影响本地新标签页使用
5. **令牌过期体验**：云笺集普通会话 30 分钟无操作过期。登录时应默认勾选「记住我」（30 天），否则每次打开新标签页都可能要重新登录——这是必须在 UI 上处理的点

### 4.4 CORS 与扩展来源

Chrome 扩展发起的 `fetch` 带 `Origin: chrome-extension://<extension-id>`。因此：

- **云笺集** `CORS_ORIGINS` 需追加该 origin（否则登录接口被拦）
- **thrilled-server** 需在自身 CORS 白名单中允许该 origin
- **扩展 ID 稳定性**：未打包加载时 ID 随目录变化。开发期可临时放宽为「允许所有 `chrome-extension://` 前缀」，但生产必须固定 ID 后再收紧（见 03 文档待决策）

同时扩展 `host_permissions` 需包含新 API 地址（如 `http://<server-ip>/*`）。

## 5. 同步模型

### 5.1 一期：快照式备份（本次要跑通的）

对应截图里的「立即备份当前界面 / 恢复为默认界面」。

- 客户端把**整份界面状态**序列化为一个 JSON payload，`POST` 上传
- 服务端按用户存储多条快照，列表展示名称 + 备份时间 + 操作
- 「恢复」= 拉取指定快照 payload → 客户端校验 schema → 覆盖本地状态
- 优点：实现最简单，数据不会丢，多端可手动搬运
- 缺点：**多端同时改会互相覆盖**（一期接受）

**payload schema（v2，2026-09-27 与内容模型对齐）** — 布局部分与 `exportLayout` 实际输出、02 §13 冻结内容模型**完全一致**；本地导出文件 = 其中的布局部分（`{ v, app, exportedAt, standard, privacy }`）

```jsonc
            "actions": ["add", "custom", "square", "setting"] },  // 当前为名称清单（同原型 DOCK_APPS）
  "settings": {
    "engine": "baidu",             // 当前引擎（name 键，见 shared/types.ts 的 EngineDef / BUILTIN_ENGINES）
    "engines": [ { "name": "baidu", "hidden": false }, { "name": "google", "hidden": true } ],  // 顺序与隐藏状态
    "autoFocus": false,
    "contextMenu": ["openMethod", "searchBar", "dockBar", "minimalMode", "hideItems", "engine", "mascot", "syncData", "siteMsg", "changelog", "about"]
  }
}
```

- 卡片实例 = `{ id, c, r, w, h, t, config }`：`c/r/w/h` 为**网格单位**（1 单位 = 60px，卡片实际像素 = 单位 × 60 − 50，四边内缩 25px，见 02 §3）；`t` 引用 `WIDGET_DEFS` 键（02 §13.1）；`config` **只存覆盖值**，读取时与定义默认值合成
- `standard` / `privacy` 为**页面数组套数组**；恢复时先过 `normPages` / `readLayoutDoc` 归一化（坏数据丢弃）
- schemaVersion 1（`mode` + 扁平 `items` + `page`/`kind`/`slot` 初稿）**作废**，无任何实现依赖

### 5.2 二期：分实体增量同步

一期跑通后，在同一套服务上叠加：

| 实体 | 键 | 冲突策略 |
| --- | --- | --- |
| `layout` | userId | 乐观锁 `revision`，冲突返回 409 由客户端选择保留本地/远端 |
| `items` | userId + itemId | 逐条 `updatedAt` 比较，新者胜；删除用墓碑（`deletedAt`） |
| `skins` | userId + skinId | 按整套风格粒度取新（含用户自建风格）；不逐令牌合并 |
| `dock` | userId | 有序 ID 列表，冲突时整列表取新 |
| `settings` | userId | 逐字段合并，本地优先 |

不做的（明确记录在 03 文档）：CRDT、实时协同、离线操作队列。

## 6. 数据模型（thrilled-server / Prisma / SQLite）

```prisma
// 云笺集账号在本服务的映射（不存密码）
model UserRef {
  id           String   @id @default(cuid())
  remoteUserId String   @unique          // 云笺集 User.id
  email        String   @default("")
  nickname     String   @default("")
  avatar       String   @default("")
  createdAt    DateTime @default(now())
  lastSeenAt   DateTime @default(now())

  snapshots  Snapshot[]
  templates  Template[]
  stars      TemplateStar[]
  applies    ApplyRecord[]
  syncDocs   SyncDoc[]
}

// 一期：界面快照（整份覆盖式备份）
model Snapshot {
  id            String   @id @default(cuid())
  userRefId     String
  userRef       UserRef  @relation(fields: [userRefId], references: [id], onDelete: Cascade)
  name          String
  schemaVersion Int      @default(1)
  payload       String                   // JSON 字符串
  sizeBytes     Int      @default(0)
  createdAt     DateTime @default(now())

  @@index([userRefId, createdAt])
}

// 界面广场：可分享的界面模板（只存数据，不存代码）
model Template {
  id            String   @id @default(cuid())
  authorRefId   String?
  authorRef     UserRef? @relation(fields: [authorRefId], references: [id], onDelete: SetNull)
  title         String
  summary       String   @default("")
  category      String   @default("other")   // work | study | home | dev | other
  tags          String   @default("")        // 逗号分隔
  coverUrl      String   @default("")
  payload       String                       // 同 Snapshot.payload schema
  schemaVersion Int      @default(1)
  isBuiltin     Boolean  @default(false)     // 种子数据标记
  status        String   @default("published") // published | hidden
  applyCount    Int      @default(0)
  starCount     Int      @default(0)
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  @@index([status, category])
  @@index([applyCount])
}

model TemplateStar {
  id         String   @id @default(cuid())
  userRefId  String
  userRef    UserRef  @relation(fields: [userRefId], references: [id], onDelete: Cascade)
  templateId String
  template   Template @relation(fields: [templateId], references: [id], onDelete: Cascade)
  createdAt  DateTime @default(now())

  @@unique([userRefId, templateId])
}

model ApplyRecord {
  id         String   @id @default(cuid())
  userRefId  String
  userRef    UserRef  @relation(fields: [userRefId], references: [id], onDelete: Cascade)
  templateId String
  appliedAt  DateTime @default(now())

  @@index([userRefId, appliedAt])
}

// 二期：分实体增量同步（一期建表不启用）
model SyncDoc {
  id        String   @id @default(cuid())
  userRefId String
  userRef   UserRef  @relation(fields: [userRefId], references: [id], onDelete: Cascade)
  kind      String   // layout | tiles | widgets | dock | settings
  payload   String
  revision  Int      @default(1)
  updatedAt DateTime @updatedAt

  @@unique([userRefId, kind])
}
```

## 7. API 契约（thrilled-server）

统一前缀 `/api/v2/*`，nginx 上暴露为 `/newtab-api/*`（避免与云笺集 `/api/` 冲突）。错误响应沿用云笺集包络：`{ error: { code, message, details } }`。

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/healthz` | 否 | 真实探活（含 DB 查询） |
| POST | `/api/v2/auth/login` | 否 | 代理云笺集登录，返回 token + user |
| POST | `/api/v2/auth/logout` | 是 | 代理云笺集登出 |
| GET | `/api/v2/me` | 是 | 当前用户（带 60s 缓存） |
| GET | `/api/v2/snapshots` | 是 | 备份列表（分页） |
| POST | `/api/v2/snapshots` | 是 | 立即备份当前界面 |
| GET | `/api/v2/snapshots/:id` | 是 | 读取快照 payload |
| DELETE | `/api/v2/snapshots/:id` | 是 | 删除快照 |
| GET | `/api/v2/templates` | 否 | 界面广场列表（`?category=&q=&sort=&page=`） |
| GET | `/api/v2/templates/:id` | 否 | 模板详情 |
| POST | `/api/v2/templates` | 是 | 发布/分享我的界面 |
| POST | `/api/v2/templates/:id/apply` | 是 | 记录应用 + `applyCount++` |
| POST | `/api/v2/templates/:id/star` | 是 | 收藏 / 取消收藏（toggle） |
| GET | `/api/v2/templates/mine` | 是 | 我的作品 |
| GET | `/api/v2/collections` | 是 | 我的收藏 |
| GET | `/api/v2/history` | 是 | 应用记录 |

**服务端必须做的校验**（否则模板体系会被脏数据毁掉）：

1. `payload` 用 zod 按 schema 校验，拒绝未知字段与超限结构
2. `payload` 体积上限（建议 512KB）与条目数上限（图标 ≤ 500、分页 ≤ 20、小组件 ≤ 30）
3. **只允许结构化数据**：`url` 校验为 http/https、`icon` 只允许 URL 或 data:image、`label` 长度限制；**拒绝任何 HTML/脚本字段**
4. 模板列表与详情对匿名可读（种子数据），发布/收藏/应用需登录

## 8. 界面广场与 MV3 硬约束

**这是本方案最重要的一条技术约束：**

> Chrome MV3 的 CSP 禁止执行远程代码。扩展**不能**从服务器下载 JS 组件并运行。

因此界面广场的模板**必须是纯数据**，由扩展内置的渲染器解释执行：

- ✅ 允许：布局结构、图标条目、Dock 顺序、小组件类型 ID + 配置参数、风格皮肤令牌值、壁纸引用
- ❌ 禁止：模板携带 `<script>`、内联事件、远程 JS 模块、任意 HTML 片段

推论：
- 「小组件」必须是**扩展内置的有限组件集**（news / music / clock / calendar / todo / ai-tools …），广场模板只能**配置**它们，不能新增组件类型
- 若要支持第三方小组件，需要走「声明式描述 + 内置渲染器」路线，而不是加载第三方代码
- 种子数据（截图里的 106 个界面）由 thrilled-server 的 seed 脚本写入，`isBuiltin = true`
- 截图里卡片上的「预览图」用 `coverUrl` 静态图片，不要求真实渲染

## 11. 风险清单

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | **无 HTTPS，Bearer token 明文过链路** | 中（个人使用、非公网目标） | token TTL 短；后续上域名 + 证书；nginx 已预留 443 模板 |
| R2 | 云笺集普通会话 30 分钟过期 | 体验差，频繁重登 | 登录默认勾选「记住我」（30 天）；扩展记录 `expiresAt`，过期前静默提示 |
| R3 | CORS 白名单未含扩展 origin | 云功能全挂 | 部署清单中固化「云笺集 `CORS_ORIGINS` 追加扩展 origin」 |
| R4 | 扩展 ID 不稳定（未打包加载） | CORS 白名单失效 | 开发期放宽为 `chrome-extension://` 前缀；生产固定 ID 后收紧 |
| R5 | **MV3 禁止远程代码** | 界面广场方案被否 | 模板只传数据；小组件为内置有限组件集（见 §8） |
| R6 | 模板 payload 脏数据 / 注入 | 渲染崩溃、XSS | zod 校验 + 体积/条目上限 + 字段白名单 + 拒绝 HTML |
| R7 | 壁纸体积（尤其视频） | 上传慢、存储爆 | 云上只同步引用（本地 IndexedDB 持有实体），不做二进制上云 |
| R8 | v3 → v4 数据迁移 | 老用户磁贴/设置丢失 | 写一次性迁移器：读旧 `chrome.storage` 键 → 转 v4 schema；保留旧键只读一段时间 |
| R9 | 视图层全量重写 | 工期与回归风险 | 一期只做固定坐标网格布局；`core/` 层不动，把重写范围限制在 `app/` |
| R10 | SQLite 并发写 | 偶发锁等待 | 独立 DB 降低耦合；启用 WAL；写操作串行化 |
| R11 | 用户自建风格无边界校验 | 令牌值畸形导致界面不可读 | 皮肤令牌写入前做白名单键 + 值格式校验；提供「还原内置」与一键回到经典风格兜底 |
