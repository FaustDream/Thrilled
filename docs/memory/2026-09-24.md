## 调研结论（依据实际代码与真实 DOM，非推测）

### 现有 Thrilled v3

- Chrome MV3 新标签页扩展，原生 TypeScript + esbuild，无 UI 框架。
- 数据层与平台层可复用（`storage.ts` / `wallpaper.ts` / `file-config.ts` / `favicon-resolver.ts` / `export.ts` / `reset.ts`），视图层（DOM 直操）几乎全部要重写。

### 云笺集（`d:\cloudletter`）

- 后端 Express 4 + Prisma 5 + SQLite，`tsx` 运行，API 前缀 `/api/v2/*`，生产 systemd 监听 `:3012`。
- 鉴权是 **Bearer Token + Session 表**（`server/src/auth.ts` 的 `extractBearer` → `requireAuth`），非 Cookie。
- 存在 `GET /api/v2/auth/me`（需登录）→ **独立服务可用它校验 token 复用账号，无需共享数据库**。
- 会话 TTL：普通 30 分钟无操作过期；「记住我」30 天。
- CORS 为显式白名单 `CORS_ORIGINS`，允许头仅 `Authorization, Content-Type`。
- 前端 React 18 + Vite + TS（`:3015`），设计规范 `docs/DESIGN-SPEC.md`：令牌阶梯 + **紫色全线禁止** + `check-tokens.mjs` 构建门禁。
- 部署：nginx + systemd，SSH 别名 `cloudletter`；**当前仅 IP + 80 端口 HTTP，无域名无证书**。

### UiTab 真实站点（本轮新增，重要）

- `https://uitab.com/tab` **只是一个 iframe 壳**，真实产品在 **`https://uetab.com/`**；直接 dump `/tab` 只会拿到空 DOM（此前多次取证失败的根因）。
- 主界面**不是分区布局**：小组件与网址图标**同处一个绝对定位网格**，可混排、可跨格。
- 布局引擎：**60px 单元格**，卡片在单元格块内**四边内缩 25px**（`尺寸 = 单位×60 − 50`）；24 列 × 10 行，固定 **1920 设计稿坐标系**、水平与垂直居中；**横向两页**，页面 N 坐标 = 页面 1 + `N×1920`。
- 卡片是**不透明白底 + 16px 圆角**（**不是**毛玻璃）；卡片下方 **14px 白色居中名称标签常驻显示**。
- 顶部：左上**悬停展开**的「极简 / 标准 / 隐私」胶囊；右上 42×42 头像；搜索栏在 `y=100`，输入框 772×54 胶囊（`rgba(255,255,255,.5)` + 2px 边框），placeholder「百度 搜索」。
- Dock：`bottom:0` 高 122、padding 16；8 个 98×98 应用位（图标 66×66）+ 4 个功能按钮（`adder` / `custom` / `square` / `setting`）。
- 小组件实测：新闻热点、熊猫Dj、AI工具合集（图标格容器）、购物、UiTab AI、天气、时钟、影音/游戏/社交（图标格容器）、收藏夹、待办、日历、**下班倒计时（单卡片多条目）**、纪念日。

## 技术要点

- **Vite 内部用 esbuild** 做 TS/JSX 转译与依赖预构建，因此「TS + esbuild」与「React + Vite」是同一套方案，不是叠加；不可混用的是 React 与 Vue 同应用双运行时。
- 选型结论：**React 18 + Vite + TypeScript**，决定性理由是云笺集已是同栈、工具链可复用。**注意：云笺集的紫色禁令不继承**——界面风格属用户可自定义的皮肤数据（用户已明确纠正）。
- **MV3 硬约束**：CSP 禁止远程代码，界面广场模板必须只传结构化数据（布局/图标/小组件配置），由扩展内置渲染器解释；小组件只能是内置有限组件集。
- 账号复用方案：thrilled-server 代理云笺集 `/api/v2/auth/me` 校验 Bearer token，本地仅存 `UserRef` 映射（不存密码），同机 `127.0.0.1` 一跳 + 60 秒缓存。
- 风险首位：无 HTTPS 导致 Bearer token 明文过链路（个人使用场景可接受，后续上域名）。
- **布局引擎换算**（UI 与数据层唯一强约束）：`slot` 用网格单位，`像素尺寸 = 单位 × 60 − 50`，`left = 240 + col*60 + 25`，`top = 网格顶 + row*60 + 25`；名称标签顶边 = `(row + h) × 60 − 24`。
- **风格皮肤系统**（本轮新增，架构级）：4 套内置主题从 CSS 硬编码改为 JS 数据 `SKINS` 驱动，令牌以行内 CSS 变量注入 `#stage`。`SkinPack.id` 由字面量联合改为**自由字符串**，`builtin` 仅标记出厂来源、不影响可编辑性。12 项可编辑令牌：卡片底/卡片文字/次要文字/强调色/名称标签/面板底/面板文字/边框线/胶囊底/胶囊文字/菜单底/菜单悬停。改动即时生效并写回该风格；`FACTORY` 快照支撑「还原内置」。

## 原型验证

用浏览器子代理实际打开原型逐项验证。

**旧版原型（第一轮，基于错误的「分区三段式」设想）修复 6 个问题**：

1. 图标 hover 名称气泡被 `.tile { overflow: hidden }` 裁切 → 移除该属性
2. 极简模式下大时钟未隐藏、且顺序在搜索框之上 → 加 `display: none` 与 `order` 规则
3. 网址导航 9 个分类按钮总宽 439px 溢出容器 352px → 改为 `flex-wrap` 换行
4. 新闻标题照抄截图被截断的文案 → 改为完整标题，让 `text-overflow: ellipsis` 生效
5. `.widget-row` 右侧空 204px、音乐卡底部空 66px → 卡片宽度调整 + flex 补齐
6. 界面广场没有 UI 入口 → Dock 第二按钮改为「界面广场」，主题设置改由抽屉头部齿轮进入

**新版原型（按实测重写后）修复 4 个问题**：

1. 4×2 图标格（游戏/社交）竖向溢出 24px → 按容器实算图标尺寸，单元格高 <56px 时不渲染标签
2. 个性化「壁纸遮罩度」滑块读数恒为 0% → 修正百分比取整逻辑
3. 天气卡「多云转小雨」被 ellipsis 截断 → 收窄 padding/gap、温度字号 26→22px
4. 名称标签顶边公式写成 `(row+h)×60+3`，比实测多出 27px 空隙 → 修正为 `(row+h)×60−24`（卡片底边为 `−25`，标签高 20px 紧贴其下，间隙 1px）；已同步写入 02 文档 §3.1
